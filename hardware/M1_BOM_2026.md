# Prototype 001 — M1 Logger BOM (2026)

Status: purchasing baseline / read-only first

This BOM separates the passive measurement computer from later heavy perception compute. The logger should remain simple, deterministic and easy to recover even when a larger GPU computer is added later.

## Recommended starting point — M1-Lite

### Compute

**Preferred:** Raspberry Pi 5 class SBC with 8 GB RAM, active cooling and an M.2/NVMe adapter.

Why:
- enough for CAN logging, GNSS/IMU ingest, timestamping, health monitoring and one compressed video stream
- low power compared with a large AI computer
- excellent Linux/SocketCAN ecosystem
- inexpensive to replace

Do not use it as the final big-model perception computer.

**Alternative if perception should start immediately:** NVIDIA Jetson Orin Nano Super Developer Kit.

Published platform capability is up to 67 INT8 TOPS, 8 GB LPDDR5, external NVMe support and a 7–25 W power envelope. This makes it appropriate for early camera/perception experiments while still remaining much smaller than the eventual RTX-class node.

### CAN acquisition

**Preferred development interface:** PEAK PCAN-USB FD, isolated USB-C version (IPEH-004023) or USB-A equivalent (IPEH-004022).

2026 PEAK list price: EUR 278 before reseller/VAT differences.

Capabilities relevant to the project:
- Classic CAN and CAN FD
- galvanic isolation
- Linux support
- USB host connection

For the F13 first acquisition stage, one interface is enough to start. Add channels only after we know which BMW networks actually need simultaneous capture.

**Upgrade option:** PCAN-USB Pro FD for two CAN-FD channels plus LIN where useful. PEAK 2026 list price: EUR 566.

### GNSS + inertial reference

**Preferred development/evaluation device:** u-blox C102-F9R application board / ZED-F9R family.

Useful properties:
- multi-band GNSS
- integrated IMU/dead reckoning
- RTK capability
- time-pulse output
- USB/UART
- configurable CAN on the evaluation board
- wheel-tick/direction inputs on C102-F9R

The module can output fused GNSS+DR data at rates up to 30 Hz in priority navigation mode and provides a timing pulse suitable for synchronization work.

For M1 we still retain an independent host timeline and BMW-motion comparison rather than trusting one fused navigation source as ground truth.

### Storage

1 TB NVMe minimum for the first logger.

Preferred properties:
- TLC NAND if affordable
- good sustained write performance
- SMART/health reporting
- replaceable rather than soldered storage

2 TB becomes preferable once multiple cameras are enabled.

### Forward camera

Start with one front camera only.

Requirements before model-specific selection:
- hardware exposure timestamp or best achievable deterministic timestamp
- stable Linux driver
- 1080p minimum
- 30 fps minimum; 60 fps preferred for motion analysis
- known lens/FOV
- manual exposure controls
- fixed focus
- no proprietary cloud dependency

Do not buy the full surround-camera set until the first camera/timestamp pipeline is validated.

### Vehicle power

Use a dedicated automotive power path rather than a consumer USB car adapter.

Required functions:
- fused 12 V input
- load-dump / transient protection
- reverse-polarity protection
- undervoltage shutdown
- ignition/wake sense
- graceful shutdown hold-up time
- 5 V high-current rail for Pi or suitable regulated rail for Jetson

The logger must never be able to flatten the BMW battery during parked development.

### Wiring / breakout

Use a removable passive harness so the first stages require no cutting of the BMW loom.

Include:
- fused power branch
- ground reference
- CAN breakout points
- labelled twisted-pair leads
- service disconnect
- test points

At M1-Lite the harness is strictly read-only from the autonomy computer side.

## M1-Lite+ — immediate perception option

Replace the Raspberry Pi logger compute with, or add alongside it:

**NVIDIA Jetson Orin Nano Super Developer Kit**

Published European reference pricing is around EUR 239 from NVIDIA pages, with local reseller/VAT variation. It provides up to 67 TOPS and external NVMe support.

Recommended architecture even here:

```text
BMW buses / GNSS / IMU
        |
        v

        |
        +----> disk
        |
        +----> perception processes
```

A perception crash must not destroy the raw drive log.

## M1-Full logger

Add only when M1-Lite data proves the need.

### Multi-bus capture

Options:
- multiple isolated PCAN-USB FD units
- PCAN-USB Pro FD where two CAN channels + LIN are sufficient
- later dedicated multi-channel interface

The first priority is simultaneous timestamp quality, not maximum channel count on paper.

### FlexRay

FlexRay is an M1-Full addition, not a blocker for first logging.

A professional Vector-class FlexRay interface is the most straightforward route for protocol-level capture, but cost is materially higher than CAN. Current used-market examples for a VN7610 FlexRay/CAN interface have appeared around EUR 730; professional tooling/licensing compatibility must be verified before purchase.

Do not buy a random FlexRay interface before confirming:
- Linux/Windows driver strategy
- raw capture API availability
- required Vector licensing/software
- transceiver/piggyback configuration
- ability to receive passively on the BMW network

### Surround cameras

Expand only after synchronization is proven:
- front narrow/tele
- front wide
- left repeater/side
- right repeater/side
- rear
- optional near-field parking views

Every camera must have a calibration ID and timing health state.

### Networking

Use wired Ethernet between logger and perception compute.

Preferred progression:
- 1 GbE adequate for metadata + compressed streams
- 2.5 GbE useful when several high-quality streams move between nodes
- 10 GbE only when measurements prove the need

## Separate perception / big-model computer

The logger BOM should not be distorted to accommodate the final autonomy compute.

Planned hierarchy:

```text
M1 logger
  | raw synchronized evidence
  v
perception compute
  | world state / model outputs
  v
openpilot-derived planner / shadow stack
```

Early perception: Jetson Orin Nano Super class.

Later high-end path: x86 host + NVIDIA RTX-class GPU, while retaining the small logger as the evidence recorder and independent health source.

## Current recommended first basket

For the lowest-risk start:

- Raspberry Pi 5 class logger
- 1 TB NVMe
- PEAK PCAN-USB FD isolated
- u-blox ZED-F9R/C102-F9R class GNSS/IMU
- one Linux-friendly forward camera
- protected automotive DC/DC supply
- passive BMW breakout harness

This is sufficient to begin P001-B through P001-E of the acquisition plan without purchasing the final autonomy computer.
